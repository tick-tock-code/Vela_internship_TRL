**Core aim**
Do LLM-engineered structured features improve prediction over a human-engineered baseline, and do LLM-reasoned features add useful signal beyond those structured features?

**Data and starter materials** 
The project will use VCBench, a founder success dataset containing founder profile information and outcome labels. A starter package of example scripts and utilities has been prepared, this includes:
- A baseline modelling script (vcbench_lambda_features_minimal.py) with 15 candidate human-engineered features, LLM-generated lambda features, and a combined mode
- An LLM-reasoned features example (vcbench_reasoned_features.py) showing how to use an LLM to make subjective judgments about each founder's profile
- A README (README_vcbench_minimal_examples.md) explaining setup, usage, and the differences between feature types
- A shared datasets utility module for loading and parsing VCBench data

While we provide a shortlist of 15 human-engineered features, you are encouraged to do your own exploratory data analysis (EDA) and develop additional features based on what you find — exactly as a ML engineer would approach a new dataset. The provided features are a starting point, not a ceiling. The example code includes suggestions for further features you might explore.
All work should initially be carried out within the training set only, using a clean cross-validated setup. Once a final approach has been selected, it can be applied to the test set for evaluation.
Note that while LLM calls for generating candidate features are usually inexpensive, evaluating LLM-reasoned features at scale can become slower and more costly, since it requires repeated batched API calls across many founders. This should be considered when deciding how many reasoning-based features to test.


**Project Goal**
Your goal is to build and compare a small number of feature sets.
At minimum, you should compare:
- Human baseline features
- Human + LLM-engineered structured features
- Human + LLM-engineered structured features + LLM-reasoned features
Example human baseline features might include prior founder experience, education indicators, company pedigree, domain experience, and other count-based or boolean profile features.
Example LLM-engineered structured features might include things like founder-market fit indicators, technical leadership signals, or exposure to high-growth environments, provided they are implemented as deterministic code.
Example LLM-reasoned features might include judgments such as level of domain expertise, narrative coherence, execution credibility, or strength of founder-market fit.

**Suggested Method**
A good default approach is to run three clean ablations:
- Model A: Human features only
- Model B: Human features + LLM-engineered structured features
- Model C: Human features + LLM-engineered structured features + LLM-reasoned features

Use a simple predictor unless there is a strong reason not to, for example:
- logistic regression
- elastic net
- a small tree-based model

The aim is to test the value of the features, not to turn this into a modelling competition.

**What to Measure**
Possible evaluation metrics include:
- PR-AUC
- ROC-AUC
- precision at top-k
- F0.5
- feature importance or coefficient inspection
- performance differences across ablations

It is also useful to inspect some examples manually:
- where do human and LLM-structured features agree or disagree?
- where do LLM-reasoned features seem to add something extra?
- what kinds of founders seem most helped by the new features?

**Minimum Deliverable**
At minimum, the project should answer:
- Do LLM-engineered structured features improve predictive performance over the human baseline?
- Do LLM-reasoned features add signal beyond the structured feature sets?
- Which feature bucket seems most useful?
- Are the resulting features interpretable and plausible?
- A simple, clean result is enough.

**Scientific Red Lines**
Please keep the following in mind:
- keep the setup simple
- do the ablations cleanly
- avoid leakage
- develop models in a cross-validated way within the training set
- do not overclaim noisy or unstable LLM judgments
- a null result is still useful

**Suggested 1-Week Plan**
Day 1

Run the starter code
Implement the human baseline features (provided shortlist + any new features inspired by your EDA)

Day 2
design and test candidate LLM-engineered structured features
implement a first small batch

Day 3
design and test LLM-reasoned features
add them to the pipeline

Day 4
run the ablations
inspect feature importance and example cases
begin writing up the results

Day 5
