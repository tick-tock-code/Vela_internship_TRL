> raw features → represent/compress A/F appropriately → then run your two adjustment tracks on that transformed design

The cleanest way is to keep your track logic, but change **what counts as the “new features.”**

## The key idea

Right now, “new features” means the raw A or F variables.

After adding PLS/PCA/SPLS/grouping, “new features” should mean:

* **A/F latent components**, or
* **A/F grouped summaries**, or
* **A/F sparse selected grouped features**

That way, your two-track setup still makes sense.

---

## Recommended structure

Suppose you have:

* `X_base` = existing larger HQ feature set
* `X_new_raw` = A and/or F raw features

Build a representation map:

* `X_new_repr = transform(X_new_raw)`

Then run the same two tracks:

### Track 1: Adjust only new features

Fit the representation only on A/F, while leaving the base features untouched.

So the model sees:

* `X_base` unchanged
* `X_new_repr` instead of raw A/F

This answers:

> “If I regularize/compress only the new reasoning block, does it still add value?”

This is probably your most interpretable track.

---

### Track 2: Adjust the entire set of features

Now allow the full design to be transformed or jointly regularized.

There are two versions of this, and they are not equivalent:

#### 2A. Partial transformation

* keep `X_base` raw
* replace only A/F with `X_new_repr`
* then run LR / selector on the full combined set

This is often the safest default.

#### 2B. Joint transformation

* transform `X_base + X_new_raw` together

This is only appropriate for methods where a joint latent space makes sense, and usually hurts interpretability. I would **not** start here.

So in practice, your “adjust the entire set” track should usually mean:

> the whole model is refit on the combined feature set, but only the A/F block is pre-compressed/grouped.

## How this maps to each method

## 1. PLS

Best way to insert it:

* Fit PLS **only on the A/F block**
* Choose `n_components` by inner CV
* Replace raw A/F features with PLS scores

Then:

* Track 1 = base raw + PLS(A/F), with only the PLS block treated as the new block
* Track 2 = same combined matrix, but let the downstream selector/regularization adjust across all features

This preserves your track logic and fixes A/F collinearity.

### Why this is clean

PLS is supervised, so it should be fit **inside each training fold only**. Never on the full dataset before CV.

---

## 2. PCA

Same insertion point as PLS:

* PCA on A/F only
* replace A/F with PCA components

This is simpler, but weaker methodologically because it is unsupervised.

---

## 3. Sparse PLS

This can act as both:

* representation
* selection

So:

* run SPLS on A/F only
* output either sparse components or selected transformed features
* feed those into your existing two-track setup

This is probably the nicest “one-step” fix if implemented carefully.

---

## 4. Sparse Group Lasso

This fits slightly differently.

Here, you do **not** create a transformed feature block first. Instead, the grouped penalty becomes the adjustment mechanism itself.

So your tracks become:

### Track 1: adjust only new features

* apply grouped penalty to A/F only
* leave base features unpenalized or lightly penalized

### Track 2: adjust entire set

* apply grouped penalty across all features, with groups defined for A, F, maybe HQ blocks too

This is elegant, but more invasive because it changes the downstream model rather than just the preprocessing block.

---

## 5. Supervised feature grouping

This is very compatible with your current setup.

Procedure:

* cluster A/F features into supervised groups
* create one representative per group:

  * average
  * weighted average
  * first PC within group
  * group PLS score

Then replace raw A/F with grouped summaries.

That plugs straight into both tracks with minimal disruption.
