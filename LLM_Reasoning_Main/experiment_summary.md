# Experiment Summary

This note summarizes the two experiment blocks that were run. It reports **validation** and **private-test** performance of human, llm-engineered, and llm-reasoned models side-by-side.



**Definitions:**

**Human Legacy features**

Features manually designed by a human from exploratory analysis of the training data. These are hand-crafted variables intended to capture signals already identifiable through standard feature engineering.



**LLM-engineered features**

Structured features generated by an LLM from a small selection (in this case 100) of the founder/company dataset. These aim to reproduce or extend human feature engineering automatically, but without adding separate subjective reasoning outputs.



**LLM-reasoned features**

Additional subjective features derived from prompting the LLM to reason about the founder or company more abstractly. These were designed to capture signals not already encoded in the human or LLM-engineered features.





## What was run

There were two main parts:

1. **Part 1: 3x3 human / engineered / reasoning block**

   * 3 Human Legacy baselines: HL-1, HL-2, HL-3
   * 3 LLM-engineered feature sets: set 05, set 08, set 07
   * 3 LLM-engineered + reasoning variants: set 05 + A/E, set 08 + A/E, set 07 + A/E
   * Model family: **XGBoost only**
2. **Part 2: 2x4 HQ mirror / reasoning block**

   * 'HQ Mirror' represents the human-made feature set created by Yagiz, that we decided represented a benchmark of performance on the test set - **F0.5 = 0.285.** It is called mirror just because I mirrored the GitHub page he created for it.
   * **The benchmark used XGBoost with decision trees of depth 1 (stumps)** - this type of model was found to improve performance of all human/llm-engineered models on the validation set, so was used in part 1.
   * Feature combos: **HQ**, **HQ + A+E**, **HQ + A+D+E+F**, **HQ + D**

     * **Prompts to create LLM-reasoned features were named experiments A through F.** These were kept subjective, to try and extract information not captured by human/llm-engineered features.
     * Each prompt was run separately, then features derived from each experiment were added in different combinations to fit to a model.
     * **Experiments D, A+E, A+D+E+F, were expected to capture a range of complexity,** to investigate how reasoning features can improve predictions of successful founders.
   * Model families: Each model in part 2 was created with **Logistic Regression** and **XGBoost**

Validation numbers come from the paper report (mean +/- std across folds). Private-test numbers come from predictions made on the test set with private success values.



Logistic regression was run in sklearn.

## Part 1 — Human vs Engineered vs Engineered+Reasoning

### Family-level validation and test summary

**'Human Legacy'** was a feature-set created by a human, after exploratory data analysis of the train set.

### Part 1 per-model validation vs test

|Family|Experiment|Validation F0.5 (mean +/- std)|Test F0.5 (avg over 3 folds)|

### Part 1 interpretation

* On **validation**, the strongest family was **LLM-engineered + reasoning**, with a family mean of **0.277 +/- 0.002**.
* Within the **LLM-engineered (no reasoning)** family, the best set was **Engineered set 05** with **0.261 +/- 0.066** on validation.
* On the **private test set**, **Engineered set 05** was also the best overall Part 1 model with **0.2969**, so it remained the best-performing **LLM-engineered** set in this block.
* The reasoning-augmented variants look **overfitted to train/validation** relative to private test. Their family-level validation mean was the highest (**0.277 +/- 0.002**), but their family-level private-test mean fell to **0.2028**, well below the plain LLM-engineered family (**0.2727**).
* The clearest overfitting example is **Eng set 05 + A/E**, which scored **0.280 +/- 0.069** on validation but only **0.1212** on the private test set.

## Part 2 — HQ mirror with Logistic and XGBoost

### Validation vs test table

|Feature combo|Logistic val|Logistic test|XGBoost val|XGBoost test|
|-|-:|-:|-:|-:|
|HQ|0.234 +/- 0.041|0.2684|0.233 +/- 0.027|0.2737|
|HQ + A+E|0.281 +/- 0.042|0.2225|0.280 +/- 0.055|0.2582|
|HQ + A+D+E+F|0.339 +/- 0.043|0.2243|0.301 +/- 0.042|0.2604|
|HQ + D|0.249 +/- 0.021|0.2482|0.235 +/- 0.029|0.2638|

### Part 2 interpretation

* The strongest **validation** model in this subset was **HQ + A+D+E+F (Logistic)** at **0.339 +/- 0.043**.
* The strongest **private-test** model in this subset was **HQ (XGBoost)** at **0.2737**.
* **HQ + D** was more robust on test for **XGBoost** (**0.2638**) than for **Logistic** (**0.2482**), despite having lower validation performance than A+E or A+D+E+F.
* Across this 2x4 comparison, **XGBoost** was the best choice on the private test set for **HQ**, **HQ + A+E**, and **HQ + D**, while **HQ + A+D+E+F** still underperformed the plain HQ baseline on test.
* This block shows a similar pattern to Part 1: richer reasoning combinations produced stronger validation scores, but those gains did not reliably carry through to the private test set.

## Overall takeaway

* **Part 1: LLM-engineered features on average match the benchmark.**
* **Part 1: LLM-engineered set 05 performed better than the benchmark** - it was also the highest performer of human/llm-engineered on the test validation.
* **Part 1:** Reasoning features **overfit on train/validation**. The reasoning family won on validation but was the weakest family on the private test set.



* **Part 2:** the highest private-test score came from the **plain HQ mirror with XGBoost**, suggesting that the extra reasoning features did not consistently translate from validation gains into private-test improvements.



* **Conclusion:** These results show that LLM-engineered features can match or improve on human engineered features. The addition of LLM-reasoning features led to overfitting of the models, and therefore poor generalisation on the test set.
